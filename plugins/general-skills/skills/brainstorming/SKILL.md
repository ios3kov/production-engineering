# Brainstorming

Help the user escape repeated default ideas. Separate **exploration** from **selection**; do not pre-kill possibilities with premature feasibility judgments.

## Entry

Identify one of two states:
- **Stuck:** outputs all look alike, previous suggestions were rejected, or the problem framing is narrowing imagination.
- **Seed:** there is a promising starting concept that needs more directions.

## Generate

1. State the real job-to-be-done, independent of the assumed solution. Ask a clarifying question only if it will materially change the ideas.
2. List the conventional approach privately/briefly as a baseline to **avoid**.
3. Shift at least two meaningful axes: who benefits, when it happens, delivery medium, price model, scale, mechanism, incentive or distribution.
4. Propose several options that differ in underlying mechanism, not only name or styling.
5. For each viable candidate, explain in one or two sentences: unusual insight, intended user, why it might work, biggest assumption and cheapest validation.
6. Let the user select an axis or candidate before moving into detailed execution, unless they asked for a finished recommendation.

## Quality gate

Ask: would independent people generate essentially the same list? If yes, deliberately reframe. Label speculative novelty as speculative. When the user asks whether something is genuinely new or exists on the market, research competitors rather than asserting originality.

Be concise, concrete and varied; use a short shortlist rather than pages of generic brainstorming filler.
