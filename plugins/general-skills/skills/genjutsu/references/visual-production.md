# Visual production supplement

Use the relevant sections inside Genjutsu's existing workflow. This is not a new gate for every task. It applies mainly to communication graphics and concept work; native UI, accessibility and existing project requirements remain authoritative. A clear small correction does not require a concept exercise.

## Subject relevance

State the intended audience takeaway. Identify which aspect of the product, person or message makes the visual choice useful. Mentally substitute another subject: unchanged meaning is a reason to investigate generic decoration, not an automatic rejection. Approved templates, recurring brand series, familiar interface patterns and plain informative designs are legitimate. Novelty is optional when it does not improve the user's goal.

## Production brief

Prepare only the fields needed for the deliverable, keeping already agreed decisions:

- **Output contract:** requested pixel dimensions, aspect ratio, medium, safe areas, crop variants and export needs. Do not replace exact user dimensions with conventional presets. State any unsupported output requirement.
- **Composition:** focal element, relative scale and placement, hierarchy, negative space, and what must remain visible across crops. Distinguish measured geometry from approximate directions.
- **Content:** approved text verbatim, its language and placement, and required factual details. Do not invent dates, claims, labels or logos. Do not remove required information to meet an arbitrary word limit.
- **Treatment:** appropriate typography, materials, palette and lighting, constrained by the existing brief. These are choices, not universal requirements.
- **Invariants:** approved assets, identity-defining features, exact branding and content that must not change.

Before editing, confirm an available target image or asset actually exists; ask for it when missing rather than inventing one. Use only an available, authorized production tool and its actual interface. A detailed brief cannot guarantee exact rendering. For long or error-prone copy, use an image/background plus editable typography in a suitable layout tool when available. Otherwise disclose the limitation instead of promising error-free text.

## Identity and product truth

Adapt the art direction to supplied identities. Preserve identity-defining features of a person or product unless the user requests a change. For precise logos, labels and product shapes, prefer authorized original assets or controlled compositing over invented replacements. Follow the host's requirements for a user photograph and image edits.

For FSTR or other product demonstrations, use verified outputs from the named tool and relevant settings/build when claiming a real result. Keep an illustrative concept explicitly labeled; do not present generated decoration as proof of a plugin effect, UI feature or measured performance. Missing test access means the claim is unverified, not that it is permissible to fabricate the result.

## Review and repair

When a render is available and the host permits inspection, keep these judgments separate:

| Axis | Question |
| --- | --- |
| Message | Is the intended information understandable at its actual viewing size? |
| Audience | Does the treatment suit the viewer, medium and approved brand? |
| Concept | Does the visual choice support meaning rather than just adding novelty? |
| Execution | Are text, geometry, crop, contrast, identity and unwanted artifacts correct? |

Do not turn these judgments into a universal numeric quality score. Mark taste judgments as such; do not imply user testing, accessibility certification or a rendered inspection without evidence. A simple useful design can pass. An elaborate but confusing one needs revision. If inspection is unavailable, record NOT_RUN rather than claiming that the output was reviewed.

Repair the cause within the user's scope and agreed budget:

- **Concept problem:** reconsider the direction while retaining valid facts and constraints.
- **Composition problem:** adjust placement, scale or crop; preserve the approved idea.
- **Text problem:** correct or typeset the text; do not regenerate unrelated elements.
- **Identity or factual problem:** restore the real asset or remove/qualify the unsupported claim.

Recheck the affected result. If the same failure recurs after a targeted correction, change the production method rather than endlessly repeating the same generation. If the necessary tool is unavailable, report the remaining defect without claiming completion. No automatic full redesign or forced palette change follows a request to reread the rules.
